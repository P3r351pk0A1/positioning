# CODEBASE AUDIT (2026-05-19)

Документ для сопровождения проекта: что реально используется, какие алгоритмы включены, что можно безопасно чистить.

## 1) Актуальные подходы и алгоритмы

### Архитектура

- Активный код: `src/positioning`.
- Запуск: CLI `positioning` (`src/positioning/cli.py`) и UI (`src/positioning/streamlit_app.py`).
- Форматы входа: 4-канальные `CSV/WAV` + sidecar metadata JSON.

### Модель и конфиг

- Датамодели: `MicrophoneArray`, `Environment`, `AudioFrame`, `PairDelay`, `TdoaEstimate`, `LocalizationResult`.
- Конфиг из JSON: геометрия решетки, аудио-параметры, среда, режим локализации.

### Предобработка

- Разбиение на окна с overlap.
- DC removal, Hann window, frequency mask.
- Диагностика окна: energy + inter-channel correlation.

### Оценка задержек (TDOA)

- Основной алгоритм: GCC-PHAT.
- Дополнительно:
  - интерполяция пика (`interpolation`);
  - субполосный режим (`subbands`);
  - temporal delay continuity (`unwrap`) между соседними окнами;
  - fallback на full-band GCC-PHAT для узкополосного сигнала.

### Валидация/робастность TDOA

- Физическая допустимость задержек.
- Транзитивность на тройках микрофонов.
- Отбраковка пар по качеству.
- Робастная оценка с перебором подмножеств пар + Huber-подобная функция потерь.

### Локализация

- `direction` (дальнепольный): оценка единичного вектора направления + азимут/угол места.
- `position` (ближнепольный/расширенный): 3D оценка позиции с диагностикой надежности.

### Трекинг

- EMA-сглаживание углов.
- Подавление резких низкоуверенных скачков.
- Производные (скорость изменения углов), агрегированная уверенность.

### Синтетика

Поддерживаемые источники (`simulation.py`):

- `sine`
- `pulse`
- `chirp`
- `multitone_burst`
- `band_noise`
- `am_fm_tone`

### Визуализация

- Tkinter popup: `visualization.py`.
- Streamlit 3D dashboard: `streamlit_app.py`.
- Для `direction` режим визуализации сравнивает углы (фиксированный радиус), а не дальность.

## 2) Что можно удалить (кандидаты)

Ниже список именно кандидатов на удаление/чистку. Разделено на “безопасно” и “после подтверждения”.

### 2.1 Безопасно удалить/не хранить в Git

Служебное и кэш:

- `.pytest_cache/`
- `src/positioning/__pycache__/`
- `tests/__pycache__/`
- `src/positioning.egg-info/`

Промежуточные артефакты:

- `data/logs/*` (если не нужен архив экспериментов)
- `data/processed_*/*`
- `data/pmi/*` (если протоколы уже перенесены в отчет)

### 2.2 Кандидаты на удаление после подтверждения (дубли/устаревшие данные)

Синтетические дубликаты (частично перекрывают друг друга):

- `data/synthetic/direction_far_curve_sine.csv`
- `data/synthetic/direction_far_curve_sine2.csv`
- `data/synthetic/direction_far_curve.csv`
- `data/synthetic/direction_far_curve_amfm.wav` (уступает `direction_far_curve_amfm_v2.wav`)

Документы/черновики вне основного контура:

- `docs/notes.txt`
- `docs/TZ.txt` (если ТЗ хранится в основном документе диплома, а не в репо)

PDF-артефакты (восстановимы скриптом):

- `docs/pdf/*` (если хранить только markdown-источники и генерировать PDF по запросу)

### 2.3 Неиспользуемые фрагменты кода (точечные)

- Удален в ходе ревизии: неиспользуемый импорт `metadata_truth_points` в `cli.py`.
- Удален в ходе ревизии: неиспользуемый импорт `Vec3` в `tdoa.py`.
- Потенциально на удаление: функция `metadata_truth_points` в `visualization.py` (сейчас не вызывается в runtime-коде).

## 3) Рекомендуемая политика чистоты репозитория

- Держать в Git только исходники (`src`, `tests`, `configs`, `docs/*.md`, `tools`).
- Генерируемые данные (`data/logs`, `data/processed*`, `data/pmi`, `docs/pdf`) не хранить в основной ветке.
- Для воспроизводимости оставить ограниченный curated-набор `data/synthetic/*` без дублей.
