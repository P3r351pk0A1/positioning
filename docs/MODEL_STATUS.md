# Состояние модели и готовность проекта

Документ фиксирует фактическое состояние Python-проекта после реализации этапов 1-4 и 6-10.

## Общая готовность

Активная версия проекта находится в `src/positioning`.

Проект собирается и запускается как Python-пакет. Основные команды:

```powershell
python -m pip install -e ".[dev]"
positioning demo --config .\configs\default.json
positioning validate --config .\configs\default.json
positioning pmi --output-dir .\data\pmi --repeat-count 100
python -m pytest
```

## Реализованные этапы

### Этап 1. Рабочая Python-структура

Готово:

- активный код вынесен в пакет `src/positioning`;
- CLI-точка входа находится в `src/positioning/cli.py`;
- вспомогательные обертки оставлены в `tools/demo.py` и `tools/validate.py`;
- C++-код сохранен только как архивный референс в `legacy_cpp`;
- `__pycache__` не должен отслеживаться;
- добавлен `pyproject.toml` для editable-установки;
- pytest используется как основной способ проверки.

### Этап 2. Модель данных и конфигурация

Готово:

- `MicrophoneArray` проверяет число микрофонов, размерность, невырожденность и компланарность;
- `Environment` хранит температуру, влажность и рассчитанную скорость звука;
- `AudioFrame` описывает четырехканальные аудиоданные;
- `TdoaEstimate` хранит задержки, качества, веса и пары;
- `LocalizationResult` хранит режим, координаты, направление, углы, статус, невязку и диагностику;
- `configs/default.json` задает решетку, аудио, среду и режим локализации;
- загрузчик конфигурации проверяет отсутствующие поля, число микрофонов, частоты, overlap и параметры среды.

### Этап 3. Офлайн-вход и синтетические сигналы

Готово:

- генератор синтетического 4-канального сигнала по точке источника;
- поддержаны шум, задержки, ослабление, одиночный выброс и отраженный путь;
- реализованы CSV и WAV вход/выход;
- рядом с сигналом сохраняются JSON-метаданные сценария.

### Этап 4. Предварительная обработка

Готово:

- разбиение потока на окна фиксированного размера;
- удаление постоянной составляющей;
- нормализация каналов;
- Hann-окно;
- частотная маска по заданной полосе;
- диагностика информативности окна по энергии и межканальной согласованности.

### Этап 5. Оценка TDOA из аудио через GCC-PHAT

Готово:

- реализован GCC-PHAT для пары каналов;
- задержка имеет тот же знак, что и модель `arrival_i - arrival_j`;
- поиск пика ограничивается физически допустимым временем по расстоянию между микрофонами;
- рассчитывается качество пары по отношению основного пика к боковому фону;
- для всех шести пар микрофонов формируется `TdoaEstimate`;
- добавлены субполосный режим (`subbands`) и temporal unwrap (`delay continuity`) для неимпульсных сценариев;
- добавлена CLI-команда `positioning localize-audio`;
- файловый конвейер работает как `CSV/WAV -> окна -> предобработка -> GCC-PHAT -> локализация -> трекинг -> CSV/JSON`;
- добавлены unit-тесты GCC-PHAT и smoke-тест CLI.

### Этап 6. Подавление ложных задержек

Готово:

- проверка физической допустимости задержек;
- проверка транзитивности задержек для троек микрофонов;
- отбраковка пар с низким качеством;
- робастный перебор подмножеств пар;
- Huber-подобная оценка остаточной ошибки;
- явная диагностика использованных и отброшенных пар.

### Этап 7. Локализация направления и координат

Готово:

- режим `direction` для дальней зоны;
- перевод направления в азимут и угол места;
- режим `position` для ближнепольной/расширенной 3D-оценки;
- в результате явно указан режим;
- для 3D-режима выдаются невязка, число использованных пар и признак надежности.

### Этап 8. Сглаживание во времени

Готово:

- хранение истории результатов по окнам;
- экспоненциальное сглаживание азимута и угла места;
- отбраковка резких скачков при низкой уверенности;
- оценка скорости изменения направления;
- агрегированная уверенность по нескольким окнам.

### Этап 9. Выходные данные и журналирование

Готово:

- JSON-вывод одного результата;
- CSV-журнал по окнам;
- сохранение параметров среды, окна, задержек, невязки, доверия и статуса;
- разделение пользовательского вывода CLI и подробного машинного журнала;
- понятные сообщения для ошибок конфигурации, чтения файлов и неинформативных сигналов.

### Этап 10. Испытания по ПМИ

Готово:

- автоматизированный запуск ПМИ через `positioning pmi`;
- Markdown-протокол;
- JSON-результаты;
- CSV-таблица;
- проверка запуска, файлового режима, среды, фильтрации, TDOA, отражений, направления/координат, логов, времени обработки и нештатных ситуаций.

Последний прогон: 15 из 15 проверок пройдено.

## Ограничения

Главное оставшееся ограничение - не алгоритмическое, а макетно-измерительное: GCC-PHAT реализован, но для реальных аудиозаписей надо проверить синхронность каналов, аппаратные задержки, ориентацию направленных микрофонов, отражения и отношение сигнал/шум.

Также надо учитывать физику одиночной компактной решетки:

- режим `direction` является основным для дальней зоны;
- режим `position` применим для допустимых ближнепольных сценариев и синтетической проверки;
- точная дальность в дальней зоне по одной плоской решетке не должна заявляться как гарантированный результат.

Визуализация в `direction` режиме интерпретируется только как угловая:

- отрисовка выполняется на фиксированном радиусе;
- сравнение качества проводится по угловой ошибке (`truth_angle_error_deg`), а не по метрической дальности.
