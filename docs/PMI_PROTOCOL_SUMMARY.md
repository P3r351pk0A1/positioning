# Протокол ПМИ

Документ фиксирует состав автоматизированных испытаний по ПМИ и результат последнего прогона.

## Команда запуска

```powershell
positioning pmi --output-dir .\data\pmi --repeat-count 100
```

Выходные файлы:

- `data/pmi/ПРОТОКОЛ_ПМИ.md`;
- `data/pmi/pmi_results.json`;
- `data/pmi/pmi_results.csv`.

## Итог последнего прогона

Пройдено 15 из 15 проверок.

| № | Проверка | Статус | Что подтверждает |
| --- | --- | --- | --- |
| 1 | Запуск программы | пройдено | CLI и базовый сценарий локализации запускаются без ручной подготовки |
| 2 | Прием четырех каналов и метаданных | пройдено | CSV-сигнал из четырех каналов и sidecar-метаданные корректно записываются и читаются |
| 3 | Обработка файлового режима | пройдено | Поддерживаются CSV и WAV входы |
| 4 | Учет температуры и влажности | пройдено | Изменение среды меняет скорость звука |
| 5 | Фильтрация сигнала с шумом | пройдено | Шумное окно проходит предобработку и получает информативную диагностику |
| 6 | Оценка TDOA из аудио через GCC-PHAT | пройдено | GCC-PHAT восстанавливает задержки из синтетического четырехканального импульса |
| 7 | Корректность TDOA на синтетике | пройдено | Оценка направления по синтетическим задержкам совпадает с эталоном |
| 8 | Подавление отраженного пути | пройдено | Одиночная ложная TDOA-пара отбраковывается |
| 9 | Вычисление направления и координат | пройдено | Работают режимы `direction` и допустимый `position` |
| 10 | JSON/CSV-выход и журнал | пройдено | Результат и пооконный журнал сохраняются в структурированном виде |
| 11 | Время обработки окна | пройдено | Предобработка одного окна быстрее длительности окна |
| 12 | Отсутствие одного канала | пройдено | Некорректное число каналов отклоняется понятной ошибкой |
| 13 | Некорректные параметры среды | пройдено | Неверные температура/влажность отклоняются |
| 14 | Недостаточная информативность сигнала | пройдено | Тихое окно получает статус недостаточной информативности |
| 15 | Длительный повторный прогон | пройдено | Повторная последовательная обработка завершается стабильно |

## Назначение проверок

ПМИ проверяет не отдельную формулу, а готовность практического программного стенда:

- программа запускается из командной строки;
- конфигурация читается из JSON;
- четырехканальный файловый вход работает;
- параметры среды участвуют в расчете;
- сигнал проходит предобработку;
- TDOA извлекается из аудиоокон через GCC-PHAT;
- TDOA-решатель корректен на синтетике;
- ложные задержки не разрушают оценку;
- режимы направления и координат явно различаются;
- выходные данные пригодны для отчета;
- нештатные ситуации не приводят к непонятному traceback;
- длительный повторный прогон не ломает состояние трекера.

## Как использовать результаты в отчете

Для отчета удобно включить:

- таблицу из этого документа;
- файл `data/pmi/ПРОТОКОЛ_ПМИ.md` как полный машинно сформированный протокол;
- `pmi_results.csv` как приложение или исходник таблицы;
- `pmi_results.json` как подтверждение структурированного формата результата.

## Ограничение протокола

Проверка GCC-PHAT выполняется на синтетическом широкополосном импульсе с известными сдвигами каналов. Для аппаратного макета протокол надо расширить реальными WAV/PCM-записями и калибровкой межканальных задержек.
